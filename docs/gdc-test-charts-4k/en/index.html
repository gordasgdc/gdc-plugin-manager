01 · WHAT THEY ARE AND WHO USES THEM

Images with a known answer,
for a tool with an unknown one.

A test chart holds values defined mathematically. Pass it through a colour transform, a LUT or a plugin and, knowing what should come out, you can see where the result drifts: on the neutral axis, in hue, at high saturation, in the shadows or in the highlights.

  1. 1

    Colourists and DITs

    Check that a camera transform or a look does not break neutrals, skin or gamut.

  2. 2

    OFX, DCTL and LUT developers

    Compare your implementation with the reference values and ROIs in the manifests, across 23 spaces.

  3. 3

    Research and ACES workflows

    The same content in ACES2065-1, ACEScg, ACEScct, DaVinci Wide Gamut and the main cameras' log encodings.

  4. 4

    Teaching and documentation

    Illustrate what a log curve, a wide gamut or banding means, on reproducible, freely licensed images.

02 · THE DATA CONTRACT

What a file contains, exactly.

Preview ≠ measurement data

The gallery images are WebP files rendered for sRGB screens and may be clipped. They are for browsing. For any measurement use the EXR file from the archive, never a screenshot or a preview.

Format
OpenEXR, RGB, float32 (IEEE binary32), lossless ZIP compression.
Resolution
3840 × 2160 pixels.
Nature
Scene-referred, full-range. No tone mapping, no display rendering, no clipping.
Values
Negative values and values above 1 are intentional (gamut stress, headroom, sub-black). Do not clip them on import.
Construction
Each chart is composed once in ACES2065-1 (AP0, linear), then converted: XYZ D65 (Bradford) → target gamut → target curve. Identical code values in two configurations are NOT the same colour.
Metadata
For every file: ROIs (pixel rectangles), reference values (XYZ D65, target linear, code), intended tests, limitations, provenance and SHA-256.

03 · GALLERY BY FAMILY

12 families, 25 charts.

Each family has one or more variants (A, B, C). Select an image to enlarge it; the larger version loads only then.

01

Colorimetry

Check a transform's accuracy on 24 reference patches, 21 neutral steps, primaries, hue trajectories and gamut-stress points. The extended variant adds LCh slices, gamut boundaries and a ΔE ladder.

02

Skin

02A holds constructed skin-tone values: ITA grid, illuminants, exposure and trajectories. 02B is a synthetic bust, an ILLUSTRATION for testing spatial masks, with no reference values.

03

Exposure

Patch ladders in 1-stop, 1/3-stop and Zone System steps, colour versus exposure, headroom, and continuous ramps in log or linear stops. They show where tones compress or shift.

04

Saturation and hue

Saturation sweeps at constant or variable luminance, hue and chroma wheels, hue ramps, hue linearity and hue × luminance interaction. Useful for spotting hue skews.

05

White balance

Illuminants × reflectances, tint shift (Duv), five chromatic-adaptation methods (CATs) and near-neutral error grids, including skin versus neutral under different illuminants.

06

Halation and bloom

Point sources of different sizes and intensities, coloured emitters, edges, contrast transitions, neon lines and veiling glare, to see how light spreads in film or lens effects.

07

Focus and MTF

Slanted edges for the slanted-edge method, Siemens stars, zone plates, chirps, line pairs and low-contrast edges, for estimating resolution and micro-contrast.

08

Grain and noise

08A is the CLEAN reference, without noise. 08B has NOISY variants with controlled Gaussian noise and a fixed seed, labelled as such. Start from the clean one and compare with the effect of a grain or denoise tool.

09

Shadows

Near-black steps, sub-black and negative values, a crush scale, low-light ramps, the zero crossing and shadow chroma. They show where shadows are lost or tinted.

10

Highlights and roll-off

Steps and ramps in the highlights, saturated highlights, single-channel overload, emitters and gamut-compression probes. They test how a look or DRT behaves at the top end.

11

Gradients and banding

Very narrow neutral ramps with simulated 10, 8 and 6-bit quantisation, hue gradients, low-amplitude chroma, near-black and near-white gradients and 2D gradients. They expose banding in a processing chain.

12

Lens and optics (synthetic)

A straight grid for distortion, flat fields, a point-source array and tangential/sagittal edges over 3×3 field positions. They are SYNTHETIC patterns for correction tools, not lens measurements.

sRGB preview (clipped), not measurement data.

05 · HOW TO USE

From download to first measurement.

  1. Choose the configuration

    Start from the space in which what you test will run. For an OFX expecting DaVinci Intermediate use dwg_davinci_intermediate; for a camera IDT use that camera's configuration.

  2. Import into Resolve

    Extract the ZIP, then drag the EXR files from the configuration folder into the Media Pool. For comparisons, put a single configuration on the timeline.

  3. Declare the input space exactly

    Tell Resolve which gamut and curve the values are written in: through the project's colour management (the clip's input space) or a Color Space Transform node. Gamut and curve must be the ones named by the configuration.

  4. Avoid a double transform

    If the project already converts the input, do not add a second conversion for the same space. The EXR file carries no transfer curve for Resolve to guess: you declare the conversion.

  5. Compare with the references

    Open the chart manifest (docs-metadata archive): the ROIs give you the rectangles to measure, the reference values the linear target and the expected code. Measure real pixels, as the mean of an ROI.

  6. Interpret with care

    A deviation shows a tool's behaviour, not a certification. Read the limits in the next section before drawing conclusions.

shasum -a 256 gdc-test-charts-4k-1.0.0-complete-part1of3.zip

Extracting

Standard ZIP: double-click on macOS (Archive Utility), “Extract All” on Windows. Every archive has its own top-level folder, so several archives never collide. The EXR files are stored without recompression; extraction is quick, but you need disk space (about 3.1 GB for the whole library).

07 · LIMITS, STATED PLAINLY

What these charts are NOT.

  • They are synthetic.

    The images are generated procedurally; they are not camera captures and not measured physical charts. The ColorChecker (CC24) values are published nominal CIELAB averages adapted to D65; physical lots differ by about 1–2 ΔE.

  • They certify nothing.

    They are not a calibration or certification for monitors, lenses or cameras. Nominal data and illustrations are different things: the synthetic bust 02B and family 12 (lens and optics) are illustrations/simulations, and the bust has no reference colour values.

  • Technically validated, not visually approved.

    The generator is labelled 1.0.0-proto. Its internal report records 32,364 automated checks with 0 failures; we did not rerun it for publication, we verified file presence, sizes and SHA-256 against the catalogue. The charts' layout has not been visually approved by a person (the layout review is pending).

  • 08B contains noise, on purpose.

    08A is the clean reference; 08B has variants with controlled Gaussian noise (fixed seed), labelled as such. The quantised rows of 11A are quantised in the stored code domain, per configuration.

  • The generator is not included.

    Version 1.0.0 publishes the resulting files, manifests and checksums, not the generator's code. Reproducibility is checked through SHA-256 and the manifests.

09 · FREQUENT QUESTIONS

Short answers.

Is it really free? Do I need an account or an app?

Yes. You download straight from GitHub, with no account, no payment and no GDC app.

Why several ZIPs instead of one?

A GitHub asset can be at most 2 GiB and the library is about 3.05 GB. It is split by configuration into three parts of at most 1.1 GB, which extract as ordinary archives.

Can I use the charts in a commercial product or a paid course?

Yes, with attribution and a pointer to CC BY 4.0, including a note of any changes you made.

Which configuration should I pick if unsure?

Pick the space in which the tool under test works. For a DaVinci YRGB Color Managed workflow dwg_davinci_intermediate is a starting point; for ACES, acescct_ap1 or acescg_ap1_lin.

Does it work in software other than DaVinci Resolve?

Yes, they are standard OpenEXR files. Any application that reads float32 EXR can use them; the colour-space declaration is made in that application.

Why are some values negative or above 1?

Because they test behaviour at gamut limits, headroom and below black. If a tool clips them, that deviation is exactly the information you are after.

May I redistribute the archives on my site?

Yes, with attribution. Keep SHA256SUMS.txt and the link to the original page so users can verify integrity.
